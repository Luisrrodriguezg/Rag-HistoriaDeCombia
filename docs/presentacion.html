Problema

Lo que duele

El conocimiento histórico de Colombia está disperso en enciclopedias, libros y artículos. Responder una pregunta puntual con respaldo requiere consultar varios documentos a mano.

Lo que entrega el agente

Un chatbot que responde con citas verificables sobre los documentos cargados, se niega a inventar cuando no hay contexto, y sugiere temas alternativos cuando la pregunta queda fuera del corpus.

Agente con LangGraph

START → retrieve → classify → decide_route ├── refuse_with_topics → END └── generate (stream) → END

retrieve

Embebe la pregunta con bge-m3 y trae los top-12 chunks de pgvector por similitud coseno.

classify

1 sola llamada al LLM. Decide relevancia y, si NO, extrae temas del corpus para sugerir.

generate / refuse

Streaming token-a-token con qwen2.5:14b, o ensamblaje sin LLM del mensaje de rechazo con sugerencias.

Los últimos 3 turnos del usuario se inyectan como historia → follow-ups con pronombres funcionan.

Base vectorial y carga de documentos

pgvector

  • Postgres 16 con extensión vector
  • Columna VECTOR(1024) en tabla chunks
  • Índice ivfflat con vector_cosine_ops (100 listas)
  • Una sola BD para metadatos + embeddings

Pipeline de carga

  • Upload POST /documents (multipart)
  • Extracción: pypdf · python-docx · UTF-8
  • Split 800 chars / 120 overlap
  • Embed con bge-m3 → vector 1024-d
  • Insert bulk en chunks con FK

Formatos soportados: PDFDOCXTXTMD

Seguridad y usuarios

Keycloak

  • Realm rag importado al boot
  • Cliente público rag-frontend
  • Flujo Authorization Code + PKCE S256
  • Auto-registro habilitado, rol por defecto user

Backend

  • Validación RS256 contra JWKS (cache TTL)
  • Rotación lazy si aparece nuevo kid
  • Todo endpoint excepto /health exige Bearer JWT
  • Sesión persiste, logout limpio desde UI

Control de alucinaciones (4 estrategias)

3Prompt estricto: prohibido inventar nombres/fechas/cifrasgenerate
4Auto-rechazo: el modelo emite el mensaje canónico si el contexto no sirvegenerate

El prompt cierra explícitamente la rendija de los disclaimers ("aunque no se menciona en tu contexto...") que permitía filtrar conocimiento paramétrico del modelo.

Demo — Preguntas con respuesta válida

Demo — Refusal y follow-up con memoria

"¿Quién ganó el mundial del 94?" → refusal con sugerencias · "Los presidentes donde nacieron" → follow-up sin sujeto explícito que funciona gracias a los últimos 3 turnos inyectados al prompt.

Conclusiones

  • Menos compuertas, mejor producto. Consolidamos grade_documents + grade_generation en una sola classify: menos refusals erróneas y menos latencia.
  • El embedder es la palanca más importante. Cambiar de nomic-embed-text a bge-m3 (multilingüe) movió la calidad de recuperación más que cualquier ajuste del LLM.
  • La trazabilidad SSE cambia la UX. Ver los nodos avanzar en vivo hace que ~5 s de latencia se sientan productivos.
  • Hardware local con Metal es suficiente para un RAG interactivo de calidad — qwen2.5:14b-q5_K_M responde en ~1–2 s con 100 % GPU.
